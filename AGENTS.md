# Collaboration and remote checkpoints

The owner requires completed work to be tracked remotely because multiple sessions work on this repository.

- After each completed logical step, commit the relevant changes and push the working branch, even when there is no pull request. Do not leave completed work solely in local files.
- When sessions share a checkout, use a separate branch and worktree for your work. Stage only your own changes.
- Preserve the inputs, proposals, meaningful verification and review evidence needed for another session to reproduce or continue the work. Keep temporary caches, dependencies and generated renderer bundles out of commits.
- Confirm the remote branch SHA after pushing. Report the branch and latest commit in the handoff.
- Use normal fast-forward pushes. Creating a checkpoint branch does not authorize merging it, replacing the active apartment design, or deploying it.

This instruction records the owner's explicit request on 9 October 2026.
